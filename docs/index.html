01 / 完全多模态

不是切一次模型，
就丢一次上下文。

Yan 把模型角色拆为三类，互不抢占。文本、图像、视频可以同时存在；生成、编辑、预览、下载和会话持久化是一条链路。同一会话修改媒体时复用资源 ID，无需下载再上传。

01

主模型 · 文本

负责理解用户、规划、工具调用、代码修改和最终回答。多厂商动态目录，按文本 / 视觉输入 / 图片输出 / 视频输出分类。

OPENAI · GROK · GLM · DEEPSEEK · QWEN · DOUBAO · KIMI · YI · HUNYUAN · SILICONFLOW
02

次模型 · 图像

生成或编辑图片，结果回到主模型上下文，由主模型向用户解释和交付。支持 auto、1:1、4:3、3:4、3:2、2:3、16:9、9:16、21:9。

GENERATE · EDIT · RESOURCE REUSE
03

次模型 · 视频

生成或编辑视频，结果同样回到主模型上下文。媒体模型可不选；不选就不会出现在任务里，也不会伪装成可用。

GENERATE · EDIT · CONTEXT RETURN

视觉中继

RELAY

主文本模型不能读图时，由 GLM-5V Turbo → 4.6V Flash → 4.1V Thinking Flash → 4V Flash，或 Agnes 2.5 Flash → 2.0 Flash 接力。只报告它实际看到的事实，不替代主模型执行任务。

不自动复读

NO WASTE

生成图片或视频后不会因为"结果存在"而自动调用 read_image 再读一遍。只有任务确实需要视觉理解、主模型不能读图或用户明确要求时，才走视觉中继或读图工具。

上下文压缩

CONTEXT

内核按模型上下文窗口管理预算，默认约 70% 处进入软压缩，约 85% 处显示硬安全线。压缩前后 token、阈值、上下文窗口和压缩次数会被记录并可见。

缓存观测

CACHE

每次完成运行可查看真实缓存读取量、输入总量和缓存命中率——不是估算值，不是固定百分比。不同会话、不同厂商、不同上下文的命中率会不同。

02 / 完整软实力

把复杂度放进内核，
把能力放进工作区。

Yan Kernel 是唯一执行权威。它把模型连接到受权限约束的工具、工作区和验证流程。没有被需要或没有配置的服务不会伪装成可用工具。

Yan Kernel

基于 OpenCode 1.18.11 二次开发的执行权威。事件结构化、DeepSeek DSML 兼容、错误熔断、独立总结阶段、运行结果可审计。

RUNTIMEEVENTSDSML

内置浏览器

ChatGPT 风格工作面板。打开、读取、点击、输入、选择、悬停、拖拽、滚动、截图、检查页面。Agent 不抢用户正在看的页面。

BROWSER MCPVERIFY

Yan Skills

查找、安装、读取、列出、移除 Yan 管理的 Skill 与设计参考。代码辅助、UI 美化、网页设计、Agent 规则、办公辅助分类管理。

MARKETCODEUIOFFICE

MCP 服务

JSON-RPC 2.0 over stdio。设置页填写启动命令、测试连接、启用 / 停用、删除。每个任务保存自己的工具快照，任务之间不互相覆盖配置。

JSON-RPCSTDIO

记忆与上下文

全局记忆与工作区记忆按 global / machine / workspace 区分。隔离审阅器只提候选事实，敏感内容和疑似提示注入会过滤。

MEMORYREVIEW

审阅、回滚与 Git

本次运行的文件、增删行、diff 和单文件审阅；Git 工作区支持状态、分支、暂存、提交、抓取、拉取、推送和文件差异。二进制文件从审阅列表过滤，但媒体仍可预览。

DIFFROLLBACKGIT

CodeGraph · Serena

工作区代码图、索引和结构关系。Serena 负责代码定位与定点编辑辅助。Understand Anything 开箱即用打开知识图谱。

CODEGRAPHSERENAUA

权限与提问

请求批准 / 替我审批 / 完全访问三档策略。折叠面板而非强制弹窗，显示即将执行的命令，提供"总是允许 / 本次允许 / 拒绝"。

PERMISSIONAPPROVAL

辅助对话

02+ / 桌面操控

让 Agent 落到真实桌面，
不锁键鼠，Esc 即停。

Yan Computer Use 是 1.4.0 的初始集成：通过官方 Nuphus MCP 的 desktop_* 工具，Agent 可以激活窗口、理解界面、定位控件并执行点击、输入、截图等操作。只有真实桌面工具开始执行时才进入操控态；屏幕边缘显示蓝色光效，顶部提示“Yan Agent 正在操控你的电脑，按 Esc 退出”。

v1.4.0 · Initial Integration

不是远程控制，是带边界的桌面协作

  • 权限边界：桌面工具仍受当前任务的访问策略、工作区规则与权限判断约束。
  • 窗口激活流程：Skill 要求操作前激活目标窗口，焦点可能变化时再次激活。
  • 不抢占用户键鼠：Agent 执行动作的同时，用户仍可自由操作。
  • Esc 一键中止：全局热键立即退出电脑操控模式，覆盖层与热键同步清理。
  • Skill + MCP 协作：yan-computer-use Skill 约束观察与验收流程，Nuphus MCP 执行原生桌面工具。
初始集成说明 Yan Computer Use 依赖 Nuphus MCP、目标软件可访问性与视觉感知质量；复杂 Canvas、自绘界面或权限窗口仍可能失败。这是 1.4.0 的实验性能力，不是全应用自动化承诺。

04 / 边界

现在能做什么，
也明确不做什么。

一款可靠的 Agent 必须把边界写在官网上。以下内容对应当前 1.4.0 的真实状态，不把未来能力包装成今天的承诺。

1.4.0 已支持

适合日常开发、资料处理和工作区内的可复核任务。

  • Windows 桌面工作区与真实 PTY 终端
  • Yan Kernel · Skill · MCP · 内置浏览器
  • 常规 / 计划 / 目标 三种工作方式与权限
  • 完全多模态：文本、图片理解、图片与视频生成
  • Yan Computer Use 桌面操控（初始集成）
  • Git 工作区：状态、分支、提交、推送、拉取、diff
  • 上下文压缩、长期记忆与审阅面板
  • 第二代 Yan Agent Pet 与移动端远程控制

正在开发

有明确计划，但不属于 1.4.0 的稳定承诺。

  • Yan Agent GUI：计划随 v1.5.0 上线
  • 移动 Web UI 尚未同步完成，不建议作为主界面
  • 常驻子 Agent 与动态并发调度
  • PowerShell 7 专属运行时切换
